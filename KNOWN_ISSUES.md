# Known Issues & Honest Limitations

1. **Hosted Environment Isolation**: Google AI Studio runs in an isolated Linux cloud container and cannot install Chrome extensions, register Windows/macOS/Linux Native Messaging hosts, or access browser tabs on the user's workstation. Local Browser Session Mode must be tested on the user's machine after exporting the repository.
2. **Live Provider DOM Selectors**: None of the 7 provider adapters are marked `LIVE_VERIFIED` because live authenticated browser sessions on third-party AI websites cannot be exercised from the hosted sandbox. Provider websites occasionally change CSS classes or DOM structures; use the built-in **Diagnostics -> Run Selector Check** view locally to detect UI drift.
3. **Tool Calling in Browser Session Mode**: Ordinary web chat UIs do not expose native structured JSON function-calling schemas. WebSession2API explicitly returns `HTTP 422 UNSUPPORTED_CAPABILITY` when a coding agent sends `tools[]` to a text-only browser session rather than fabricating tool calls. Use **Official API Mode** for full native tool-calling workflows (e.g., Claude Code).
4. **CAPTCHA / Cloudflare / Rate Limits**: WebSession2API intentionally does not bypass CAPTCHAs, Cloudflare Turnstile challenges, or upstream rate limits. When detected in a browser tab, the adapter transitions to `captcha_required` or `rate_limited` so the user can resolve the challenge directly in Chrome.
5. **Ephemeral Master Key Warning**: If `WEBSESSION2API_MASTER_KEY` is not set in `.env`, the gateway generates an ephemeral in-memory encryption key for `SecretVault`, meaning Official API keys encrypted in SQLite must be re-entered after a restart. Set a persistent 32+ character `WEBSESSION2API_MASTER_KEY` in your local `.env` before storing Official API credentials.
